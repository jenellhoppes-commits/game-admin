# 代理後台與商戶後台原型規格基線

MCH／AGT｜V0.2 原型執行版｜2026-09-07

> 本文件用於製作可操作原型與第一輪核對。原型中的導覽分組、文字與顯示順序可在使用者看過畫面後調整；已確認的資料邊界、幣別、結算、權限與歷史不可改寫規則不得用展示值改寫。

## 1. 本輪目標

1. 產出兩個可各自開啟的本地原型：商戶後台、代理後台。
2. 沿用遊戲商總後台的視覺系統、名詞、狀態與同一組 Mock 主資料。
3. 所有主選單、列表、詳細頁、篩選、分頁、申請與確認流程均可操作；不只做靜態首頁。
4. 原型完成後先由規劃端核對畫面、邏輯、UI、UX 與資料邊界，再交使用者逐頁確認，之後才定版 PRD。

## 2. 三端共同基線

| 項目 | 原型必須遵守的規則 |
|---|---|
| 主資料 | 總後台為 Master。沿用 `Agent`、`Merchant`、`MerchantLine`、`Member`、`Bet`、`Transaction`、`Pool`、`Reconciliation`、`Settlement`，不得另造相互衝突的第二套資料。 |
| 代理層級 | 最多 L1、L2、L3。L3 不能新增下級；新增或移轉不得造成循環或超過 L3。 |
| 商戶關係 | 每個商戶必須有一個直接所屬代理；歷史資料以當期關係快照歸屬。 |
| 線路與幣別 | 一條線路只有一個交易幣別；會員綁定線路、幣別與錢包，不能在外部後台任意搬移或改幣。 |
| 錢包模式 | 商戶層決定 Seamless 或 Transfer；外部後台不提供任意切換。 |
| 金額 | 投注、派彩與輸贏保留原幣。不同幣別不得直接相加；總計按幣別分組。 |
| 匯率 | 商戶與代理只看最終適用或正式鎖定匯率；不顯示市場來源、內部調整或成本拆項。 |
| 結算 | 結算頁只處理登入角色自己的單據。確認、提出差異、總後台審核、鎖定為不同狀態；鎖定不代表已付款。 |
| 交易 | 注單是遊戲結果；交易是資金動作。一局可有多筆交易，不能混成同一狀態。 |
| Replay | 只還原當局歷史，不重新執行 RNG、不重算結果、不新增交易。商戶可看授權資料；代理初版不提供。 |
| 敏感資料 | 商戶與代理端均不下發 RNG Seed、內部 Math、Debug、Secret、內部風控筆記或其他對象的合約。 |
| 申請 | 外部提交只建立申請。`已通過` 與 `已生效` 分開；總後台執行成功後才改正式資料。 |
| 查詢 | 文字欄位按 Enter 等同查詢；換條件回第 1 頁；清除後恢復預設；預設 20 筆，可選 20／50／100。 |
| 返回狀態 | 從列表進詳細再返回時，保留已套用篩選、排序、頁碼與每頁筆數。 |
| 顯示 | `0`、`未取得`、`未設定`、`不適用`、`無權限`、`資料更新中` 必須分開，不得都顯示為 0 或空白。 |
| 無權限 | 後端資料投影即不傳值；不能只靠前端隱藏。深連結亦需拒絕，且不洩漏對象是否存在。 |
| 可及性 | 一般文字對比至少 4.5:1；圖示按鈕、收合選單與輸入欄都有可辨識名稱；鍵盤可完成主要流程。 |

## 3. 視覺與互動基準

- 延續總後台現有 Element Plus／Art Design Pro 語言：相同欄寬、頁首、卡片、標籤、表格、抽屜、Dialog、明暗主題與狀態色。
- 左側以工作群組收納功能，詳細頁不加入 Sidebar。選單使用既有 Iconify／Element Plus 圖示，不使用 emoji、文字符號或臨時圖形代替資產。
- 桌面以 1440×900 為主要核對尺寸；390×844 時 Sidebar 收合、內容不被遮擋，寬表格可在表格區橫向瀏覽。
- 所有主 CTA 必須有明確結果：查詢更新列表、申請產生追蹤編號、確認改變畫面狀態、錯誤保留表單內容並指出原因。
- 原型使用真實感 Mock 資料並與總後台一致，例如代理 `A00001 / AG-TW-001 / 亞洲總代理`、商戶 `M00001 / MER-0001 / NovaBet`、線路 `ASG_MER0001_TWD` 與 `ASG_MER0001_USD`。

## 4. 商戶後台原型

### 4.1 身分與資料範圍

- 預設展示帳號：NovaBet 商戶管理員。
- 僅可看 `MER-0001` 與已授權的 TWD／USD 線路。
- 可用角色：商戶管理員、營運、客服、技術、財務、稽核。角色與線路範圍取交集。
- 沒有線路授權時顯示無可用範圍，不回退成整個商戶。

### 4.2 導覽架構

| 工作群組 | 頁面 | 原型必做 |
|---|---|---|
| 首頁 | 儀錶板 | 是 |
| 營運管理 | 遊戲中心、線路管理、串接中心、會員中心、交易中心、獎池 | 是 |
| 分析與財務 | 營運報表、對帳／結算 | 是 |
| 系統 | 公告通知、帳號與權限 | 是 |

原本 11 個能力全部保留，但 Sidebar 以 4 個工作群組整理，避免一級入口過多。這是原型導覽方案，待畫面核對後定版。

### 4.3 儀錶板

- 全頁篩選：期間、線路、幣別、環境；切換環境清除不適用選取。
- KPI：投注、派彩、遊戲輸贏（投注－派彩）、投注會員數、局數、實際 RTP。
- 金額卡按原幣分組；若選「全部線路」，TWD 與 USD 各自顯示，不能顯示一個未說明幣別的合計。
- 區塊：交易異常、待確認對帳、待補件申請、線路健康。
- 卡片可鑽取至帶入相同條件的列表；返回後保留條件。
- 明示「遊戲輸贏不等於商戶營收或應付金額」。

### 4.4 遊戲中心

- 分籤：可合作遊戲、已開通遊戲、申請紀錄。
- 列表欄位：遊戲代碼、名稱、類型、裝置、語系、主檔狀態、線路開通狀態、理論 RTP 方案、限紅方案、更新時間。
- 詳細頁：基本資料、各授權線路配置、試玩能力、版本與申請歷程。
- 操作：申請開通、申請變更核准方案、申請停用。原型不提供直接修改 RTP Math 或直接開關 Production。
- 試玩只使用演示／Sandbox 資料，不冒充正式玩家。

### 4.5 線路管理

- 列表欄位：UID、交易幣別、錢包模式、環境、開通狀態、已開遊戲數、Credential 狀態、最近更新。
- 詳細頁：基本資料、遊戲配置、大廳展示設定、環境設定、申請與生效歷程。
- 操作：新增線路申請、變更 Callback／白名單／返回網域申請。
- 審核中不得先產生看似已生效的正式 UID、Secret 或開通時間。

### 4.6 串接中心

- 分籤：API 文件、環境設定、Credential 狀態、串接測試、跳轉追蹤。
- Secret 不回顯；只顯示 Credential 編號、指紋、版本、狀態、核發與到期時間。
- 測試僅針對固定 Sandbox 端點與核准測試資料；成功只更新測試紀錄，不自動啟用 Production。
- 跳轉追蹤顯示發起、Token 核發結果、跳轉結果與錯誤摘要，不顯示可重用 Token。

### 4.7 會員中心

- 查詢：會員外部識別、內部編號、線路、幣別、來源狀態、限制狀態、最後遊戲時間。
- 列表：外部識別＋線路、內部編號、幣別、餘額與來源時間、首次／最後遊戲、限制摘要。
- 詳細：基本資料、餘額來源、遊戲紀錄、注單、交易、限制與申覆紀錄。
- 不提供新增玩家、搬線路、改幣、改餘額或直接解除遊戲商限制。
- 可提出限制申覆；會員、範圍、原因與期間必填。

### 4.8 交易中心

#### 下注紀錄

- 篩選：注單／局號、會員、線路、遊戲、幣別、注單狀態、期間。
- 列表欄位：注單號、局號、會員、遊戲、線路、原幣投注、原幣派彩、狀態、下注時間、操作。
- 列表操作只保留「查看」；不放獨立盤面或 Replay 捷徑。
- 詳細頁頁籤固定順序：基本資料 → 遊戲結果 → 關聯交易 → 異常紀錄 → 重播與盤面 → 原始結果。
- 「重播與盤面」同頁呈現歷史盤面與事件重播；盤面格數依該遊戲版本，控制含上一步、播放／暫停、下一步、重新播放。
- 原始結果只顯示外部白名單資料；敏感欄位不傳值。

#### 資金交易

- 篩選：交易號、注單／局號、會員、類型、狀態、幣別、期間。
- 狀態分為處理中、成功、失敗、結果未明、已沖正；結果未明不可直接重送資金。
- 可查看關聯交易與回報差異；回報不會建立補款、退款或沖正。

### 4.9 獎池

- 僅列本商戶線路參與的同幣 Pool、級別、參與狀態、自己的貢獻與自己的中獎紀錄。
- 若共享水位未核准公開，顯示「未提供」，不得顯示 0。
- 不顯示其他商戶、會員或線路明細；申請加入／退出不改寫歷史。

### 4.10 營運報表

- 商戶端只保留一個「營運報表」入口，包含總計列與明細列表，不再拆出多個重複報表頁。
- 分析維度可切換：日期、線路、遊戲、會員；共用期間、時區、環境、幣別與關鍵字條件。
- 指標：局數、投注、派彩、遊戲輸贏、實際 RTP。會員維度需獨立權限。
- 所有金額按原幣分組；Sandbox／演示／測試身分預設排除。
- 匯出使用同一條件建立工作，生成與下載時都重新驗權。

### 4.11 對帳／結算

- 分籤：對帳單、差異單、結算單。
- 對帳單欄位：單號、版本、期間、原幣彙總、商戶條件、最終適用匯率、結算幣、方向、金額、確認狀態。
- 只有 `待確認` 且沒有未解差異的版本可以確認；新版本取代後舊確認不沿用。
- 差異回報需關聯原交易／局號、金額、幣別、說明與附件；不得修改原紀錄。
- 已鎖定結算只讀，可提出更正申請。畫面終點是「已鎖定」，不顯示成系統已付款。
- 不顯示代理成本、價差、內部匯率調整或其他商戶資料。

### 4.12 公告通知、帳號與權限

- 公告只顯示適用商戶／線路／角色的已發布內容；已讀不等於接受商務變更。
- 帳號管理支援邀請、停用、角色與線路授權；不得刪除最後一名有效管理員。
- 財務、技術秘密、會員明細與匯出分權；撤權後立即失去頁面與下載資格。
- 操作紀錄保留操作者、動作、對象、範圍、時間與結果，秘密前後值遮罩。

## 5. 代理後台原型

### 5.1 身分與資料範圍

- 預設展示帳號：亞洲總代理 `A00001 / AG-TW-001` 的代理管理員。
- 可看授權的後代樹及商戶彙總；不能向上展開、不能看到兄弟代理。
- 直屬商戶可顯示核准合作摘要；間接商戶只顯示最小識別與營運彙總。
- 初版不提供會員個資、逐筆注單、逐筆交易、Replay、Credential 或商戶技術設定。

### 5.2 導覽架構

| 工作群組 | 頁面 | 原型必做 |
|---|---|---|
| 首頁 | 儀錶板 | 是 |
| 合作管理 | 代理關係、商戶管理、商務條件 | 是 |
| 分析與財務 | 代理報表、對帳／結算 | 是 |
| 系統 | 公告通知、帳號與權限 | 是 |

原本 8 個能力全部保留，以 4 個工作群組整理。這是原型導覽方案，待畫面核對後定版。

### 5.3 儀錶板

- KPI 分開顯示：直屬下級數、後代代理數、直屬商戶數、覆蓋商戶數。
- 原幣營運卡：投注、派彩、遊戲輸贏、局數、活躍線路會員數；會員只能顯示去重數量，不能鑽取個資。
- 待辦：關係申請、合作申請、條件申請、待確認對帳、待補件。
- 沒有核准收益算法時，收益區顯示「計算規則待確認」，不填 0、不用價差推算正式收益。

### 5.4 代理關係

- 提供樹與列表兩種檢視，使用相同授權與有效日期。
- 節點資訊：代理編號、名稱、全域層級、直接父節點摘要、合作狀態、生效期間、直屬商戶數。
- L1 可展開授權 L2／L3；L2 可展開授權 L3；L3 不顯示新增下級 CTA。
- 操作：新增下級申請、停用申請、移轉申請；送出後顯示申請與執行兩個狀態。
- 驗證：上級存在、層級相鄰、無循環、整個子樹移轉後不超過 L3。

### 5.5 商戶管理

- 分籤／篩選：直屬、間接；名稱／代碼、直接代理、合作狀態、幣別。
- 欄位：商戶代碼、名稱、直接所屬代理、關係生效日、直屬／間接、狀態、核准交易幣別、線路數、原幣營運摘要。
- 詳細只提供商務與彙總資訊，不提供 Credential、Callback、IP、Secret 或內部錯誤。
- 原型只允許為本代理直屬合作提出新增商戶申請；替下級代理申請暫不開放。

### 5.6 商務條件

- 分籤：我的條件、可見的直屬商戶條件、申請紀錄。
- 顯示版本、計算基礎、比例、生效起迄、週期、結算幣與狀態。
- 只有基礎與期間一致時才顯示直接價差，單位為百分點；價差不是收益金額。
- 間接商戶的直接價差不標為本代理收益；未核准提案不進報表或結算。
- 變更只建立申請版本；跨結算期計算未定時不產生正式收益。

### 5.7 代理報表

- 代理端只保留一個「代理報表」入口，包含總計列與明細列表，不拆重複報表頁。
- 分析維度：代理、商戶、遊戲、幣別；共用期間、時區、樹範圍、直屬／間接與幣別條件。
- 指標：商戶數、線路數、局數、投注、派彩、遊戲輸贏；不含逐筆會員與資金交易。
- 直屬與間接集合互斥；父樹總額不可再加子樹總額；原幣不可跨幣相加。
- 參考換算若出現，需標示匯率時間、缺率與「非正式結算」；缺率不補 1。

### 5.8 對帳／結算

- 只列「本代理」為結算對象的單據，不能替下級或商戶確認。
- 單據欄位：單號、版本、期間、關係／條件／算法／匯率快照、原幣基礎、結算幣、方向、金額、確認與鎖定狀態。
- 沒有正式算法、歸屬規則或必要匯率時不生成正式金額；顯示缺失原因。
- 代理可確認或提出差異；總後台負責鎖定、作廢與更正。
- 鎖定不代表付款；不暴露其他代理完整合約或內部成本。

### 5.9 公告通知、帳號與權限

- 只顯示本代理組織適用的公告、申請與自身對帳提醒，不推送下級每筆財務通知。
- 本代理管理員只管理自己員工，可配置授權後代範圍、商務欄位、財務與匯出權限。
- 不能管理下級代理員工、商戶帳號或總後台角色；撤權後會話與下載資格失效。
- 操作紀錄保存歷史，不因帳號停用而刪除。

## 6. 原型暫定處理（不視為最終商業決策）

| 未決事項 | 原型採用的安全呈現 |
|---|---|
| 商戶緊急停用遊戲 | 只提供「提出緊急停用申請」，不直接改 Production。 |
| Credential 首次交付與輪替 | 只顯示狀態、指紋與申請入口，不展示 Secret。 |
| Jackpot 共享水位 | 未有公開設定時顯示「未提供」。 |
| 商戶退款／Jackpot 是否納入儀錶板口徑 | 指標旁標示口徑，不把未決項併入正式金額。 |
| 上級是否可看下級完整商務條件 | 僅自己與直屬、已授權摘要；間接完整條件不下發。 |
| 代理多層收益算法 | 不顯示預估金額，顯示「計算規則待確認」。 |
| 商戶或代理移轉後歷史查閱 | 僅保留自己的已鎖定結算；有爭議營運明細先阻擋。 |
| 暫停代理是否連動整個子樹 | 原型顯示影響評估提示，不自動連鎖停用。 |

## 7. 必做操作情境

### 7.1 商戶端

1. 切換 TWD／USD 後，儀錶板與報表同步更新且不跨幣相加。
2. 從待確認對帳進詳細、回報差異，再返回列表並保留條件。
3. 從 B00003 注單列表進詳細，操作「重播與盤面」，再返回後仍只顯示原查詢結果。
4. 送出遊戲開通或線路設定申請，看到固定申請版本、追蹤編號與 `已送出／未執行`。
5. 使用無會員明細權限的角色開啟深連結，收到無權限結果且頁面資料不存在於前端。

### 7.2 代理端

1. 展開 L1→L2→L3，L3 不可再新增下級；嘗試循環或超層級時被阻擋。
2. 在直屬／間接商戶間切換，計數與列表相符且沒有重複加總。
3. 比較相同基礎的條件時顯示百分點價差；基礎不同時顯示不適用。
4. 報表切換不同幣別只顯示該原幣總計；選全部幣別時分幣列示。
5. 只能確認自己的代理對帳；嘗試其他代理單號時拒絕且不洩漏內容。

## 8. 原型驗收門檻

- 兩個原型各有獨立本地網址，重新整理後主要路由可直接開啟。
- Sidebar 所列頁面皆可進入，不出現空白頁、僅標題頁或未接 CTA。
- 上述必做操作情境皆能以實際 UI 完成。
- 列表、總計、詳細資料與儀錶板使用同一組 Mock 資料口徑。
- 深淺模式的主要文字與控制達到對比要求；390×844 下無遮擋或不可操作區。
- Production build 成功；原型不得修改或覆蓋目前 `game-admin` 尚未提交的總後台工作樹。
- 原型完成後提供：兩個本地網址、主要頁面截圖、已完成清單、與本文件差異、仍待使用者確認的選項。

## 9. 本輪不做

- 正式 API、資料庫、SSO、付款、鏈上交易、真實 Secret、正式寄信或部署。
- 最終多層分潤公式、匯率來源、付款狀態、代理連鎖停用、歷史查閱期限。
- 玩家 CRM、充值、提款、KYC、行銷活動、推廣連結與玩家端 Replay。
- 在使用者核對原型前把原型暫定選項寫成最終規格。
