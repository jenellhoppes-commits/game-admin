# 三後台整合：第一階段執行基準

2026-09-07，使用者已授權開始。此文件優先於 V0.2 的獨立網站架構。

## 範圍與階段門檻

以 game-admin 現有工作樹為唯一總後台基礎；merchant-admin、agent-admin、partner-admin-core 只供原型參考。保留所有既有未提交修復，禁止 reset、stash、覆寫整個專案。先記錄 HEAD、差異及未追蹤來源檔案並建立本地回復副本。

本輪只完成第一階段。完成規格核對、獨立驗收及向使用者回報後，等使用者確認才進第二階段。不要部署或 push，也不要恢復安排選手流程。

## 第一階段

- 同一登入頁提供管理者後台、代理後台、商戶後台。
- 原型可帶入測試帳號，必須驗證入口與帳號相符；保留既有管理者帳號能力。
- 管理者維持原路由與現有功能；代理 /agent/*、商戶 /merchant/*，首頁分別 /agent/dashboard、/merchant/dashboard。
- 真正使用 game-admin 既有 layout、Sidebar、頁首、頁籤、主題、表格及 router，不使用 iframe、不同端口跳轉或另外掛一套 Sidebar。
- 各角色有正確選單與可查看首頁；尚未進入第二、三階段的功能明示階段狀態，不冒稱已完成，不建立假成功操作。
- 代理選單：儀錶板；代理關係、商戶管理、商務條件；代理報表、匯率報表、對帳／結算；公告通知、帳號與權限。
- 商戶選單：儀錶板；遊戲中心、線路管理、串接中心、會員中心、交易中心、獎池；營運報表、匯率報表、對帳／結算；公告通知、帳號與權限。
- 選單、角色路由、首頁及深連結一致；刷新與登出再登入正常；不允許錯誤角色 redirect。
- 退出帳號後清除原角色資料、快取與頁籤，不能殘留上一角色資料。
- 代理及商戶匯率報表為唯讀，實際功能分別在第二、三階段完成。
- 供應商對帳已移除，需回歸核對 routes/config/types/store/差異/異動紀錄沒有遺留；財務預設代理對帳，保留商戶對帳、差異處理、異動紀錄。

## 後续規則

代理最多 L1–L3，只見授權後代與商戶彙總，不提供會員個資、逐筆注單、交易或 replay；商戶只見本商戶且已授權線路。資料及頁面範圍取交集。原幣不跨幣加總，各角色只能確認自己的單據。匯率只能查詢正式適用及歷史快照，不能修改/新增/刪除/鎖定/產生快照，不顯示內部來源、加減點、成本與備註。總後台五種分析報表及指定風控/審核架構維持。未定收益算法與歷史授權不要自行定案。
