## 2. 專案層級

Project → Module（功能版塊）→ Epic（有起訖的功能群）→ 需求工作單（父工作項）→ 規格文件／開發／測試／驗收／上線五個階段子工作項。

這是平台後台功能，不採「每款遊戲一個模組」的遊戲製作模式。三個後台共用規則，以角色 Label 區分，避免同一份結轉規則開三份互不相依的實作單。

| Module       | Epic／本版交付                                                           |
| ------------ | ------------------------------------------------------------------------ |
| 權限與管理員 | 登入與帳號安全                                                           |
| 遊戲中心     | 分類與方案主檔、商戶遊戲授權、商戶限紅配置                               |
| 商務管理     | 代理關係、商戶建立、各類型商務條件、條件版本生效、幣別線路審核、串接資訊 |
| 會員管理     | 會員資料                                                                 |
| 交易中心     | 注單與交易                                                               |
| 獎池管理     | 獎池與派發                                                               |
| 客服與風控   | 告警與案件、審核紀錄                                                     |
| 財務對帳     | 對帳確認與差異、跨期交收結轉、供應商移除                                 |
| 報表中心     | 分幣營運分析、參考幣別預覽                                               |
| 匯率管理     | 幣別與匯率快照                                                           |
| 平台管理     | 公告通知、系統設定與稽核                                                 |
| 交付管理     | 三後台正式交付                                                           |

## 3. 欄位與標籤

| 欄位 | 規則 |
| --- | --- |
| Type | 每單一個；本次需求父單使用 Feature。Bug 另有重現及修復驗證。 |
| Priority | P0–P3；本文件不虛構正式優先度。先依相依順序安排，由 PM 指派。 |
| Status | 使用平台範例 Backlog／Todo／In Progress／In Review／Done，與工作區既有狀態對照後建立；不可同時把部門名當狀態。 |
| Label | 總後台、代理後台、商戶後台、後端、QA、企劃、財務規則、權限；可複選，不取代 Module。 |
| Reviewer | 開發、QA、上線子單必填組長／審核人；不得實作者自行跳過審核。 |
| Cycle | 同專案不重疊；只建目前與下一個；按固定作業階段，不能預排整條功能生命週期。 |
| 相依 | 以 blocked by 記錄；待規格拍板才開發、送測後才建立／啟動測試。 |

## 4. 五階段開立時機與完成定義

| 階段 | 建立／啟動時機 | 單一負責角色／審核角色 | 完成證據 |
| --- | --- | --- | --- |
| 需求父單 | PM 確認需求登錄 | PM／需求方 | 正式交付後才 Done |
| 規格文件 | 先與父單建立 | 企劃／PM | 規格會議拍板，Q 決策及版本有紀錄 |
| 開發 | 規格拍板且開發組長回報起訖後 | 指定工程師／開發組長 | 技術文件、PR、單測、自測與已知限制，已送測 |
| 測試 | 開發送測時建立／啟動 | 指定 QA／QA 組長 | 功能與迴歸、金額專項、Bug 關閉及複驗證據 |
| 驗收 | 測試通過後 | PM（單一 Assignee）／需求方參與簽核 | 需求方驗收紀錄與版本 |
| 上線 | 驗收及上線安排通過後 | 指定上線人／組長及 PM | 部署版本、驗證、回復方式、交付文件包 |

## 5. 狀態轉移

| 工作項 | Backlog／Todo  | In Progress  | In Review        | Done           |
| ------ | -------------- | ------------ | ---------------- | -------------- |
| 父單   | 未確認／已確認 | 任一子單執行 | 需求驗收中       | 交付完成       |
| 規格   | 待企劃         | 撰寫／討論   | 規格會議審查     | 拍板           |
| 開發   | 待組長安排     | 開發中       | 自測及組長審查   | 已送測         |
| 測試   | 待接手         | 測試中       | 修復複驗         | 測試通過       |
| 驗收   | 待驗收         | 驗收中       | 依工作區簽核規則 | 需求方通過     |
| 上線   | 待發布         | 部署中       | 依組長檢查       | 上線且文件交付 |

審查不通過退回 In Progress，直接在工作單記錄具體修改原因；聊天不能取代審核紀錄。原型部署成功不能把正式開發、測試或上線子單標 Done。

## 6. 依序建置與排程

1. PM 確認沿用／建立專案、識別碼、實際人員及狀態對照。
2. 建立功能 Module 與 Epic；先確認工作區是否支援 Epic／Work Item Types。
3. 依第五份文件建立本期需求父單與規格子單。
4. 解決影響實作的 Q；開發組長拆估並填開始日／預計送測日。
5. 先做授權與主檔，再做商務、線路遊戲、交易報表，最後做正式結轉與跨後台驗證。依第五份 blocked by 為準。
6. 開發送測時建立 QA 子單；Bug 保留重現、版本與複驗。
7. QA 通過後需求方驗收；完成上線與交付文件包才關父單。
