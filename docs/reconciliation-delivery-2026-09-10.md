# 財務核帳與交付｜2026-09-10

本次使用者決議取代先前差異自動核對及「差異未解不能確認」流程。

流程：產生結算單 → 財務核帳／交付 → 確認後鎖定。

- 系統應結金額唯讀；財務手動輸入正負差異，非零必填原因。
- 調整後應結＝系統應結＋差異。實收／實付獨立輸入，不自動變成尾差。
- 剩餘＝調整後正的可交付金額－實收／實付；可選保留至下期，包含部分收付後的剩餘款。
- 對帳狀態與收付狀態分離。交付確認鎖定；收付顯示未收付、部分收付、已收付、已結轉下期。
- 負 GGR 依既有清零／累積方式處理，獨立顯示，不輸入負實收；缺少合約方式不可猜值。
- 鎖定後禁止透過原差異處理回改金額。更正須下期「上期退款／回調」並保留來源單據。
- 原型已提供「上期退款／回調」入口，選擇同一對象、線路、交易幣及結算幣的後續未確認單據；保存來源、正負金額、原因及時間，於目標單據交付時計入一次。尚無後續單據時不可回改原單。
- 代理與商戶的對帳明細共用唯讀交付結果組件，分開呈現已鎖定及收付狀態。
- 本次已驗證手動調整必填原因、部分收付、未收付、全額收付、保留餘額、負 GGR 清零／累積、重複交付拒絕、鎖定差異修改拒絕、後續回調不修改來源。
- 本次原型以目前單據的應結與 GGR 演示交付；跨版本、正式出帳來源與精度仍按 PRD 待決項處理。
