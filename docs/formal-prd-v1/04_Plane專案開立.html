1. 流程

產生結算單 → 財務核帳／交付 → 確認後鎖定。計算依據與結算單合併呈現；不再設獨立差異案件、差異處理或結轉演示區。

2. 商務條件

只採 GGR，按遊戲類型分別設定比例，例如 SLOT 5%、LIVE 8%。這是商務成本比例，不是遊戲 RTP。下開給直屬代理或商戶的比例不得低於自身同類型成本。條件變更必有生效日並保存版本，不覆蓋歷史結算。

例：相同幣別、期間及類型的 GGR 1,000,000，代理成本 5%，下開 6%；上繳 50,000、向下應收 60,000、條件差額 10,000。例子不含差異、退款、負數抵扣與匯率。不能把條件差額直接視為平台已支付的傭金。

按對帳對象、期間、遊戲類型及幣別區分計算，不跨幣直接相加，不把商戶明細與代理彙總重複計入平台應收。結算週期沿用合約；正式切帳時區、遲到事件及取消／退款／獎池口徑須明確定義。

3. 模式及權限

角色代理統收平台代收
平台設定、查看、核帳、交付設定、查看、核帳、交付
授權代理自己的直屬單據可核帳／交付同範圍唯讀
商戶自己的單據與交付結果唯讀自己的單據與交付結果唯讀

平台可記錄實際收款方為平台或單據對應代理；代理操作時收款方固定本代理。登錄方與實際收款方分開。兩方共用原單，一方鎖定後另一方不得重複確認。模式本身不自動產生傭金支付、現金轉帳或已付款狀態。

模式變更保留生效日及紀錄。原型目前是總後台選商戶初始模式及設定未鎖定單據的本期模式（適用該期起日），完整未來生效排程尚未完成。

4. 結算欄位與核帳

結算單呈現單號、對象、期間、類型、交易幣／結算幣、模式、付款方與對應收款方；計算快照保存 GGR、商務比例／版本、匯率／版本、精度、捨入及計算時間。

交付欄位：系統應結（唯讀）、上期退款／回調、差異調整、調整原因、調整後應結、實際收款方、實收／實付、剩餘款及保留至下期。非零差異必填原因。差異由人核對外部帳目後輸入，不由系統自動推定。

調整後應結＝系統應結＋本單承接回調＋本次差異（回調若已含於系統應結不可重複加算）。原型不允許實收超過正的可交付金額；溢收處置仍需另訂規格。

所有幣別的實收／實付直接捨去小數、不四捨五入。系統應結與差異仍保留計算精度。例：應結 1,000.99、交付 1,000、剩餘 0.99，可保留至下期。負 GGR 不填成負的實收。

5. 累積與清零

負 GGR 與未交付款項是兩個不同餘額。

累積：上期負 GGR＋本期 GGR＝扣抵後 GGR；若仍為負，繼續承接；若轉正，按當期適用條件計算應結。清零：當期負 GGR 不承接下期。兩種模式均可保留尚未交付的正金額，清零不是免除欠款。

必要欄位：上期累積 GGR、本期 GGR、扣抵後 GGR、結轉下期 GGR；上期待交付金額、本期新增應結、上期退款／回調、差異調整、合計待交付、本期實際交付、剩餘及結轉下期待交付。不同類型／幣別不任意互抵。

6. 狀態與鎖定

對帳主要狀態為待確認、已鎖定；收付另列未收付、部分收付、已收付、已結轉下期。已鎖定不等於已收款；已結轉不等於已付款。

鎖定後不改原計算、模式、調整或交付；更正以後續期間上期退款／回調連結原單。原型會檢查同一對象、線路與幣別且目標單未確認。完整稽核應包含正式操作者帳號、時間及修改前後值。

7. 本次驗收結果與限制

已通過資料層自動驗收：平台在兩種模式可操作；代理統收代理可操作；平台代收代理拒絕且原單不變；非授權收款方拒絕；實際收款方與登錄方分開；整數實收；重複交付／鎖定後改模式拒絕；代理商戶共用結果及授權範圍；差異必填原因；回調不覆寫來源。型別檢查通過。

尚不能宣稱完成：多期 GGR 及未收款自動承接、正式按類型出帳及跨版本條件算法、完整模式生效排程、同一單鎖定後分次補收流程、傭金付款、自動持久化跨瀏覽器同步、後端原子鎖與正式操作者驗權。原型仍使用示範金額，登錄身份目前記錄平台／代理來源而非正式員工身份。
