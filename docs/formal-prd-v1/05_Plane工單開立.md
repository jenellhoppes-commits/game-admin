# Plane 工單開立

v1.0｜2026-09-09｜對應使用者「Plane 公單開立」；以下為可填入內容，尚未在 Plane 建單。

| 文件項目 | 內容 |
| --- | --- |
| 文件性質 | 需求父單及五階段子單的開立內容 |
| 與現有文件關係 | 對應三份 PRD v1.0 及第四份專案設定 |
| 本版目的 | 讓 PM、開發組長及 QA 可依相依與規格逐項建單 |
| 適用範圍 | 24 個父需求；每個需求五階段子單內容與驗收連結 |
| 不在本版範圍 | 實際 Plane API 操作、虛构人員／日期／PR／測試證據 |
| 上游依據 | [指定 SOP](https://cooperfu615-desinger.github.io/sop-share/)；ADM／AGT／MER v1.0 第 1、13、14、15 章 |

## 1. 使用方式與共用必填欄

本文件的 AUTH-01 等是規劃參照碼，不是 Plane 自動編號。每張正式單另填實際 Project、單一 Assignee、開始日、截止日、Cycle、Module、Type、Priority、Status、Labels、Reviewer、相依與附件。未到建立時機的子單僅預備內容，不提前啟動。

| 欄位 | 本批預填／補填規則 |
| --- | --- |
| Project | 第四份文件定義的遊戲商三後台平台；實際 ID 待 PM |
| Type | Feature |
| Priority | 待 PM 排定 P0–P3，不假造已核准優先度 |
| 開始／截止／Cycle | 待組長估工與排程；目前＋下一期 Cycle |
| 規格與原型 | https://docs.google.com/document/d/1frhoi11l_pEIDc3-T1W4l2lYJxzVGq4xlGy2CP4reoE/edit；https://jenellhoppes-commits.github.io/game-admin/#/dashboard |
| PR／技術文件／測試證據 | 建立後由責任人補真實連結；不得用本原型成功紀錄冒充正式後端測試 |
| Labels | 依該單涵蓋角色加總後台／代理後台／商戶後台；階段加企劃／後端／QA |
| Status | 父單需求已確認可 Todo；規格未拍板不得直接開發；未創建的子單無實際狀態 |

## 4. Bug 開立規則與可複製骨架

| 欄位 | 內容 |
| --- | --- |
| 標題 | [Bug][實際 Module] 動作＋異常目標 |
| 來源需求 | 填本文件參照碼與實際父單連結 |
| 版本／環境／身分 | 必填重現版本、測試環境、角色、授權範圍；不貼密碼 |
| 前提資料 | 期別、幣別、類型、版本、狀態及金額；機密去識別 |
| 重現步驟 | 依序列操作及輸入，不只附截圖 |
| 預期結果 | 引用 PRD 的具體 AC |
| 實際結果 | 可觀察數值或拒絕／放行情況 |
| 修復驗證 | 原重現案例、相邻邊界、重送、越權及歷史不變 |
| Assignee／Reviewer | 單一實作者／所屬組長；QA 複驗記錄不可省略 |
| 附件 | 錯誤紀錄、資料差異、實際測試報告連結 |
| 狀態 | In Progress → In Review；不通過退回並在單上記原因 |

這是建單骨架，不宣稱目前存在某個正式後端 Bug。不得把待產品決策當作工程師自行修正的缺陷。
