1. 這頁是什麼

功能 ID使用者要做的事核心規則
MER-01商戶儀錶板只統計本商戶授權線路；原幣分列；待辦指向自己的帳單及公告。
MER-02遊戲中心總後台未授權的遊戲不可見；已授權遊戲的主資料及 RTP 唯讀。沒有任何遊戲申請功能。
MER-03本平台遊戲開關只控制自己平台展示；不修改總後台主檔及授權。自行關閉後本後台仍看得到，依授權可重新開啟。
MER-04幣別與限紅只選總後台相符啟用方案；不可自填最低／最高金額；保存重新驗權與方案狀態；總後台可看到同筆更新。
MER-05線路管理可申請首條幣別線路；只選總後台啟用交易幣；同幣未關閉線路或待審申請存在時拒絕重複。核准前不生效。
MER-06串接中心只查看本商戶串接與可提供的文件；沒有申請紀錄。不能切換錢包、核准正式環境或暴露機密憑證。
MER-07會員中心只存取本商戶及授權線路的會員紀錄。不可透過修改識別查看其他商戶。
MER-08交易中心注單與資金交易保持關聯；重播是同一頁籤的歷史結果還原。無保存結果顯示缺少資料，不生成假結果。
MER-09獎池僅本商戶授權獎池及自身紀錄；不能改全域池或其他商戶綁定及派發。
MER-10營運報表查詢與摘要同一商戶線路集合；原幣及參考金額分開；參考不可作確認帳單的金額。
MER-11匯率報表只觀看正式適用資料及歷史，不可維護、產生快照或讀內部加點成本。
MER-12對帳／結算自身條件只讀，包含逐類型 GGR 比例及清零／累積；本商戶單據與交付結果唯讀，核帳／交付由平台或符合模式權限的代理執行。保留至下期與負 GGR 扣抵遵循共通規則。
MER-13公告通知只看本商戶授權公告；讀取不修改其他使用者閱讀狀態。
MER-14帳號與權限不可超出本商戶已授權線路；停用或撤權後停止存取；正式帳號邀請服務另需串接。

共通業務規則

規則主題內容
C01身分與資料範圍同一登入入口依帳號身分進入總後台、代理或商戶後台。服務端依已驗證身分判斷資料與操作範圍；客戶端傳入其他對象識別不會擴張授權。列表、摘要、詳細、下載及修改適用相同範圍。
C02唯一設定來源遊戲類型、幣別、RTP 方案及限紅方案由總後台維護。代理、商戶只使用授權且有效的同一來源。新設定不覆蓋歷史注單、條件版本及結算快照。
C03商務計算基準新增及修改條件只接受 GGR。有效投注與總投注不可作新商務條件基準；投注等營運統計指標仍保留。舊非 GGR 與歷史全域條件保留歷史，不自動轉換。
C04各遊戲類型獨立條件每個版本至少一個類型；同類型不可重複。SLOT 5%、LIVE 8% 為確認範例，不是全部對象預設費率。比例範圍 0–100%，最多兩位小數。留空為未設定，不能當 0%。版本共用結算幣別、週期、生效日、結算方式與原因。
C05下開成本下限上級給本代理的同類型比例是成本。下開直屬代理或商戶的比例必須大於或等於適用上級成本。5% 成本允許 5% 或 6%，拒絕 4.99%。缺少該類型成本時拒絕，不套用其他類型或舊全域比例。
C06日期與版本每次建立、修改條件必填生效日；沿用 Asia/Taipei 業務日期。過去或無效日期拒絕；同一對象同日不可有重複有效／待生效版本。新版本從生效日開始，前版本截止日不含新版本生效當日。總後台草稿經確認後排程；代理直接保存版本。同日生效，未來待生效；服務端負責到期切換及持久紀錄。
C07歷史與稽核任何版本切換不可回寫已鎖定對帳、已保存交易及歷史結果。修改留存對象、操作人、時間、動作、原因、前後值、結果及關聯版本；失敗不留下半套業務資料。重送不得重複建立或結轉。
C08原幣與參考換算列表、明細、總計使用同一查詢範圍，按原幣分組。使用者可選一個幣別預覽，必須標示「該金額只可參考」並提供匯率日期／版本。缺匯率不填 0，不把部分換算當全部總額。預覽不改應付金額。
C09清零與累積新條件必填清零或累積，不能使用「累計」。累積承接負 GGR 下期扣抵；清零下期不承接負 GGR。兩種模式均保留「保留至下期交收」，均承接尚未交收金額。既有待交收款不可因清零被刪除。
C10核帳交付與鎖定產生結算單 → 核帳／交付 → 確認後鎖定。無獨立差異案件；非零手動調整須原因。平台兩種模式均可操作，代理僅代理統收可操作授權直屬單。實收整數捨去小數，餘額可結轉；鎖定不代表收款。

3. 名詞說明

名詞說明
GGR／商務比例GGR 為計價基礎；比例是付給上級的成本百分比，與 RTP 不同。
RTP遊戲核定返還方案；例 96.2% 不是商務費率 5%。
線路／限紅線路固定一交易幣；限紅設定以商戶×線路×遊戲選方案。
商戶授權／本平台關閉總後台取消授權使商戶遊戲中心看不到；商戶自行關閉仍保留後台可見性。
上期累積 GGR／上期待交收前者未計價負 GGR，後者已計價未交收款；例如 -40,000 與 3,000 不能直接視為同一種餘額。
確認／鎖定／交收確認是帳務版本核對；鎖定限制改寫；交收才減少待交收金額。
版本／快照條件版本與實際交易、結算使用快照分離；新版本不回寫歷史。
直屬／間接直接父子或直接代理商戶關係為直屬；後代中的其他對象為間接，不重複計算。

5. 欄位說明

欄位內容與驗證無資料時顯示

條件版本／生效期間版本、起日、截止日；截止不包含新版本起日歷史缺日期顯示未提供；不可補造

本期新增交收金額本期扣抵後正 GGR 依條件計價結果必要費率或快照缺少時無法計算

本期實際交收金額本期完成交收的金額；保留為 0尚未交收／未提供，區分真實零值
結轉下期待交收金額合計減本期實際交收；後期以上期欄位承接未完成計算
匯率／快照基準幣、目標幣、適用率、生效期間、版本未提供；不產生假換算
差異關聯參照、金額、原幣、原因、處理狀態及版本無差異／未提供，依查詢成功與否區分
稽核操作人、時間、動作、原因、前後值、結果未提供；不以目前帳號補歷史操作人
線路申請原因提交申請的必要說明未填拒絕提交
歷史重播保存盤面、事件及結果版本；不是目前設定缺少資料／部分可用／不支援
串接文件只使用已核准提供的真實入口未提供，不建立虛構連結

數值 0 只用於來源已確認為零；未提供、無權限與計算失敗不得轉為零。ID 用於關聯與稽核，不以名稱做資料關聯。

各欄位是否提供以第 1 章角色權限為準；共通名詞不額外授予操作。代理端不提供 RTP／限紅配置欄位或會員明細。商戶端商務條件、RTP 及匯率均唯讀。

最新結算補充規格

本文件整合最新決議。標記為「規格」的內容不代表原型已完整實現；驗收範圍見文末。取代平台不能操作商戶單、平台代收不開放、獨立差異案件等舊規格。

1. 流程

產生結算單 → 財務核帳／交付 → 確認後鎖定。計算依據與結算單合併呈現；不再設獨立差異案件、差異處理或結轉演示區。

2. 商務條件

只採 GGR，按遊戲類型分別設定比例，例如 SLOT 5%、LIVE 8%。這是商務成本比例，不是遊戲 RTP。下開給直屬代理或商戶的比例不得低於自身同類型成本。條件變更必有生效日並保存版本，不覆蓋歷史結算。

例：相同幣別、期間及類型的 GGR 1,000,000，代理成本 5%，下開 6%；上繳 50,000、向下應收 60,000、條件差額 10,000。例子不含差異、退款、負數抵扣與匯率。不能把條件差額直接視為平台已支付的傭金。

按對帳對象、期間、遊戲類型及幣別區分計算，不跨幣直接相加，不把商戶明細與代理彙總重複計入平台應收。結算週期沿用合約；正式切帳時區、遲到事件及取消／退款／獎池口徑須明確定義。

3. 模式及權限

模式變更保留生效日及紀錄。原型目前是總後台選商戶初始模式及設定未鎖定單據的本期模式（適用該期起日），完整未來生效排程尚未完成。

4. 結算欄位與核帳

結算單呈現單號、對象、期間、類型、交易幣／結算幣、模式、付款方與對應收款方；計算快照保存 GGR、商務比例／版本、匯率／版本、精度、捨入及計算時間。

交付欄位：系統應結（唯讀）、上期退款／回調、差異調整、調整原因、調整後應結、實際收款方、實收／實付、剩餘款及保留至下期。非零差異必填原因。差異由人核對外部帳目後輸入，不由系統自動推定。

調整後應結＝系統應結＋本單承接回調＋本次差異（回調若已含於系統應結不可重複加算）。原型不允許實收超過正的可交付金額；溢收處置仍需另訂規格。

所有幣別的實收／實付直接捨去小數、不四捨五入。系統應結與差異仍保留計算精度。例：應結 1,000.99、交付 1,000、剩餘 0.99，可保留至下期。負 GGR 不填成負的實收。

5. 累積與清零

負 GGR 與未交付款項是兩個不同餘額。

累積：上期負 GGR＋本期 GGR＝扣抵後 GGR；若仍為負，繼續承接；若轉正，按當期適用條件計算應結。清零：當期負 GGR 不承接下期。兩種模式均可保留尚未交付的正金額，清零不是免除欠款。

必要欄位：上期累積 GGR、本期 GGR、扣抵後 GGR、結轉下期 GGR；上期待交付金額、本期新增應結、上期退款／回調、差異調整、合計待交付、本期實際交付、剩餘及結轉下期待交付。不同類型／幣別不任意互抵。

6. 狀態與鎖定

對帳主要狀態為待確認、已鎖定；收付另列未收付、部分收付、已收付、已結轉下期。已鎖定不等於已收款；已結轉不等於已付款。

鎖定後不改原計算、模式、調整或交付；更正以後續期間上期退款／回調連結原單。原型會檢查同一對象、線路與幣別且目標單未確認。完整稽核應包含正式操作者帳號、時間及修改前後值。

7. 本次驗收結果與限制

已通過資料層自動驗收：平台在兩種模式可操作；代理統收代理可操作；平台代收代理拒絕且原單不變；非授權收款方拒絕；實際收款方與登錄方分開；整數實收；重複交付／鎖定後改模式拒絕；代理商戶共用結果及授權範圍；差異必填原因；回調不覆寫來源。型別檢查通過。

尚不能宣稱完成：多期 GGR 及未收款自動承接、正式按類型出帳及跨版本條件算法、完整模式生效排程、同一單鎖定後分次補收流程、傭金付款、自動持久化跨瀏覽器同步、後端原子鎖與正式操作者驗權。原型仍使用示範金額，登錄身份目前記錄平台／代理來源而非正式員工身份。

本節為 v1.1 最新結算基線；正式後端待完成事項不得因原型測試通過而標 Done。

總後台「商戶管理 → 商戶詳細 → 編輯基本資料」與新增流程均提供必填的收付模式（代理統收／平台代收），編輯時帶入現值，儲存需填修改原因並記錄前後值。商戶預設模式適用後續新建帳單；既有帳單保留自身模式快照，平台可在未鎖定帳單內另行修改，鎖定帳單不得改動。代理統收允許授權代理操作，平台代收時代理唯讀；平台兩種模式均可操作。原型已補齊編輯欄位並通過型別檢查及模式權限測試；正式新期帳單產生與模式生效排程仍屬後端待實作驗收。
